# GitFit

A simple gym tracker. No accounts, no server — your data is saved in the browser on your device.

## How to open it on your computer

1. Open the `GITFIT` folder in File Explorer.
2. Double-click `index.html`. It opens in your web browser.
3. To make it look like a phone: press **F12** (Developer Tools), then **Ctrl+Shift+M** (device toolbar) and pick an iPhone from the list at the top.

After you change any code, save the file and press **F5** in the browser to reload.

Data you enter on your computer stays in *that* browser. It won't appear on your phone — use Export/Import to move it.

## Project layout

```
index.html        The page shell: top bar + an empty <main> that screens are drawn into
manifest.json     Lets the app be "installed" to a phone home screen
icons/            The home-screen icon (icon.svg and the PNGs made from it)
css/theme.css     The theme: every color, font size, corner radius and spacing as variables
css/styles.css    All styling, using only the variables from theme.css
js/library.js     Built-in exercise library and muscle list — add exercises here
js/storage.js     All saving/loading (localStorage), plus export/import
js/units.js       Converts weights, heights and cardio numbers between saved units (lbs, inches, miles, mph, feet) and shown units
js/cardio.js      Cardio's types, rules and wording: which rows today and a workout show, this week's totals, pace
js/stats.js       Works out per-muscle numbers (growth, planned sets per cycle, actual sets in the last 7 days)
js/streak.js      The weekly streak: which weeks were hit, frozen or missed, and the freezes
js/bodymap.js     The front/back muscle map drawing and its colors
js/standards.js   Published strength standards (strengthlevel.com) used by the map's Level mode
js/tabs.js        The bottom tab bar (Workouts, Cardio, Log, Profile) and the + button in it — add new tabs here; it shows only on each tab's main screen
js/views.js       Builds the HTML for each screen (this week and Next Up, Edit cycle, new workout, workout, profile, …)
js/app.js         Picks the screen from the URL and handles taps, typing and forms
```

The rule of thumb: **storage.js** knows about data, **views.js** knows about HTML, **app.js** connects them.

## Units

All weights are **saved in lbs** and heights in **inches**, whatever the Units setting says. `units.js` converts them only for display, so switching units shows old lifts converted, not relabeled. When you show or read a weight anywhere new, go through `Units.showWeight()` / `Units.readWeight()`. Cardio works the same way: distance is saved in miles, speed in mph and elevation in feet, and shown as km, km/h and meters on Metric (`Units.showDistance()`, `showSpeed()`, `showElevation()` and their `read…` partners). There's no separate setting.

## Exercises and muscles

Exercises in your workouts point at an exercise in `library.js` (or one of your custom exercises) by its id. Each library exercise has **primary** muscles (count as 1 set each) and **secondary** muscles (count as 0.5 sets each), using the muscle ids from `MUSCLE_GROUPS` (the full muscle catalog). To add a built-in exercise, add a line to `LIBRARY`.

Before you type, exercise search shows muscle group chips and your recent exercises (`Views.libraryResults()`). Once you type, it shows only the best 8 matches. How matches are ranked is in `Library.search()`.

Every finished workout also stores each exercise's name and muscles, so sets per muscle can be counted from `Store.data.sessions` (Profile's "Actual sets, last 7 days" does this).

## Adding a setting

1. Add it with a default to `DEFAULT_SETTINGS` in `storage.js`.
2. Add a field for it in `Views.settings()` in `views.js` (inside `settings-form`). Settings open from the gear on the Profile tab.
3. Read it in `saveSettingsForm()` in `app.js`.

It's then saved automatically and included in backups.

## Adding features later

- **Log** — the Log tab (the book in the tab bar) lists the exercises you've logged, most recent first, and searches the rest; each one's page (`Views.exerciseLog()`) shows an estimated 1-rep max graph (3 months, 1 year or all time; tap a dot for that day), the actual 1-rep max (heaviest weight logged for a single rep, also drawn as a thin white line on the graph), a calendar, and a day's sets with a link to the full workout. Log buttons on the workout screens and past workouts open it too, and Back returns to where you were (`returnStack` in `app.js`). Its data comes from `Store.exerciseHistory(refId)`, and the estimate from `estimateMax()` (Epley) in `storage.js`.
- **Before a workout** — tapping a workout opens its screen (`Views.workoutPreview()`), where you both look at it and change it. Each exercise is one short row (its target, and last time's sets on one line) with a down arrow; tapping it opens it up (`openPlanEx` in `app.js`) to last time's sets in full, its note, Edit and Log. Edit opens its sets and reps, Change exercise and Delete inside its card; hold and drag a row to reorder (every row shrinks to its name while one is held); + Add exercise is at the end of the list; the pencil at the top has the title, Copy workout and Delete workout (`Views.workoutDetails()`). A thin planned sets strip stays at the bottom and opens to every muscle, for this workout or the whole cycle. Start workout starts the workout and its timer, and only asks if another workout in progress would be discarded. Opened from a place in the cycle (`#/workout/<id>/<cycle item id>`), it counts as that place. An exercise's pencil also has Move to another workout.
- **During a workout** — the first unfinished exercise opens by itself, and the top strip shows sets so far. Next appears when an exercise is filled in, and suggests going heavier if every set reached the top of its range (`Store.readyForMoreWeight()`). + Add exercise for today adds to this workout only (`draft.added`): logged, but not in your plan. Tapping a weight selects it so typing replaces it.
- **Notes** — one per exercise (`Store.exerciseNote()`), kept until you change it, on the workout screens.
- **Finish summary** — after finishing, the Workouts tab shows `Views.summary()` (from `Store.sessionSummary()`): time, sets, exercises, weight lifted, new bests and workouts this week. It's only in memory, so it stays until Close or until the app is fully closed.
- **Planks** — timed: seconds are saved as the set's reps, with no weight and no estimated max. The map's Growth mode uses the longest hold (40 → 50 sec = +25%). The list of timed exercises is `TIMED_EXERCISES` in `library.js`.
- **Body weight** — the first-time setup or the card on Profile, not Settings (`Store.setBodyWeight()`). Each change is logged under that day (`bodyWeightLog`) and graphed there. Its Body weight log button (`#/body-weight`, `Views.bodyWeightLog()`) lists every weight with its date, each with Edit and Delete. Your current body weight is always the newest entry.
- **Backups** — Profile shows a reminder when there's been no backup for 30 days (`BACKUP_REMINDER_DAYS` in `views.js`).
- **Custom exercises** — listed in Settings, and can be deleted there or on their edit form. They're only marked `deleted`, so past workouts and logs keep their name.
- **Tapping something else with the exercise form open** — Back, Start workout, Log or another pencil save changes to the exercise being edited (`withFormSaved()` in `app.js`). An exercise only picked so far asks first: Add to workout or Don't add.
- **Reordering during a workout** — hold an exercise's heading row and drag it. On a planned workout the order saves to the plan for good ("Order saved"); on a quick workout it's only for that workout. An exercise added for today stays below the list.
- **A workout's plan changing while it's in progress** — apart from the order, this only happens by deleting a custom exercise in Settings. Sets already logged are never lost (`Store.keepLoggedSets()`): they carry on as an exercise added for today only.
- **First-time setup** — `Views.setup()` shows until `settings.setupDone`; anyone with older saved data skips it. It asks for workouts per week (4 is picked to start with).
- **Muscle map** — on Profile. *Growth* = for each exercise, its best estimated max (max reps on bodyweight exercises, longest hold on planks) in its first 2 weeks vs. its best in its last 2 weeks, within the last 6 weeks (`Stats.exerciseGrowth()`); a muscle's percent is the average over the exercises that train it as a primary muscle (each needs 3+ weeks logged). Secondary muscles don't count, so a muscle only trained as a secondary stays gray. The "i" by the caption explains this in the app. Tapping a muscle opens a card under the map with the exercises behind its number, each opening its log (`Views.muscleCard()`). *Level* = each muscle's best level (Beginner → Elite) among its primary exercises that have published standards, from their latest estimated max, your body weight and sex (`Stats.muscleLevels()`). The growth time span is at the top of `Stats` in `stats.js`; the color scale is `GROWTH_SCALE` in `bodymap.js`. Planned sets per muscle for one time through the cycle (`Stats.cyclePlannedSets()`; a workout in it twice counts twice) show on Edit cycle, under a heading for each muscle group. Tap a muscle to see the exercises behind its number and which workouts they're in, each opening that workout. The bars share one scale. Profile has the same list for **actual sets in the last 7 days** (`Stats.actualSets()`, every finished workout including quick ones), where each exercise opens its log.
- **The cycle (Workouts tab)** — workouts aren't on weekdays: they're a cycle you go through in order, repeating (Push > Pull > Legs > Push …), saved as the items of the split you're on (`Store.cycleItems()`; each place points at a workout, or is a rest day reminder; see **Splits** below). `Views.home()` starts with a **This week** card: the streak (a green flame while it's above 0), "2/4 workouts" (or "Week done ✓" once the week is hit), and Mon → Sun cells, each day with a finished cycle workout showing a short label from its name (`workoutLabels()`: Push P, Pull Pu, Legs L; `Streak.weekDays()`; days change at 3 am, `appDay()`). Tapping a day with a workout opens Past workouts on that day. Then **Next Up**: the workout after the one you finished last (`Store.nextUp()`, worked out from history every time, never saved, so it can't drift; quick workouts don't move it), with "last done 3 days ago" and Start workout. If the place you finished last is gone, it goes by the same workout's first place, otherwise it starts the cycle over. A workout in progress takes that card's place ("In progress", its timer, sets so far and Resume). Under it, **Then** lists the rest of the cycle in the order it's coming, each row with its small number in the cycle (the same numbers as Edit cycle, so it's clear where the cycle starts) and when it was last done; tapping one opens its screen, where Start workout is, and Next Up then carries on from whichever you do. With only one workout, the list has "+ Add your next workout". Then **Today's cardio**. **Edit cycle** (the link on Then's heading, `#/cycle`, `Views.cycleEdit()`) has the cycle: tap a workout to change its exercises, hold one (350 ms) and drag to reorder (drag code in `app.js`), ✕ on each place, + New workout, + Repeat a workout (one of your workouts in the cycle another time, the same workout and not a copy; `Views.cycleAddPicker()`) and + Add rest day, then planned sets per cycle. A workout can be in the cycle more than once, up to 7 workouts (`MAX_CYCLE_WORKOUTS`); each finished workout saves the place it was done as (`cycleItemId`, `Store.cyclePlaceFor()`). Rest days are only reminders: Next Up skips them and says "Rest day planned before this one". Removing a workout's only place deletes the workout (it asks first). The **+ button** is in the tab bar, between Cardio and Log, in the middle of the bar (a green square, so it doesn't look like a tab; `addButtonHtml()` and `ADD_OPTIONS` in `tabs.js`), on all four tabs. It opens a menu just above the bar: Quick workout, Quick cardio (the + Add cardio form), Planned workout, Planned cardio (a new planned cardio) and New split (the Create split pop-up; the new split opens on Edit cycle). Planned workout makes a new workout: with more than one split it first asks which split it goes in (`Views.workoutSplitPicker()`), then shows the usual New workout pop-up; it's added to that split without switching you to it. **New workout** is on Edit cycle (+ New workout, or "Create your first workout" / "+ Add your next workout" on the Workouts tab): a pop-up asks for its title (`Views.newWorkoutDialog()`), it's added to the end of the cycle, then its screen opens, ready to add exercises. Back from it returns to where it was made, so the next one can be made straight after. Copy opens the same pop-up filled in and makes an independent copy.
- **Splits (Switch cycle)** — you can set up several splits and switch between them. Each split is a cycle with its own name and its own workouts (`Store.data.cycles`, each `{ id, name, items }`; `Store.data.activeCycleId` is the one you're on, `Store.activeCycle()`). The Workouts tab, Edit cycle, Next Up and planned sets all go by the split you're on; your history, logs, maxes, the muscle map and the weekly streak count every split. Edit cycle shows the split's name at the top with **Switch cycle** on the right, which opens a small pop-up (`Views.cycleSwitcher()`): your splits (the one you're on says "Selected"; tap another to switch, and the pop-up stays open until Done), a pencil on each (its name and Delete split, `Views.cycleDetails()`), + Create split and Done. Create split asks for a name, then Start empty or Copy the split you're on (`Views.newCycleDialog()`, `Store.addCycle()`); a copy gets its own copies of the workouts, so changing one split never changes the other. Each finished workout saves the split it was done in (`session.cycleId`), so every split has its own Next Up and switching back to one carries on where you left it (`Store.lastCycleIndex()`). A workout in progress carries on if you switch. Deleting a split deletes its workouts (it asks first; finished workouts stay in Past workouts and your logs), and the last split left can't be deleted. Data from before version 15 becomes one split called "My split".
- **Weekly streak** — on Profile. You pick a goal of 1 to 7 workouts a week (`settings.weeklyGoal`, 4 to start: in the first-time setup and Settings). A week (Monday 3 am → next Monday 3 am) is hit when its finished workouts reach the goal (`Streak.workoutsIn()`). Every finished workout from your cycle counts, in any order and however many sets were logged, and two in one day count as two. Quick workouts don't count. A goal change counts from next week: each week keeps the goal it started with (`streak.thisWeekGoal`; before your first workout it counts straight away). Hitting your very first week earns a freeze, and so does every 4 weeks in a row (max 2); a week that ends short uses one instead of breaking the streak. Weeks judged before version 14 counted days (and before version 11, sets) and stay as they were. The rules are at the top of `streak.js`; `Streak.update()` runs on every screen draw. **Swap for today** on the workout screen saves the swapped exercise as itself, under the planned exercise's id (`swappedFrom` = the planned one), without changing the plan. The swap search also has **+ Create custom exercise**, the same form as on a workout's screen: saving it adds it to your exercises and swaps it in.
- **Finishing a workout** — if any set is still empty (no reps, or no weight on a non-bodyweight exercise), a pop-up lists them with Go back / Finish anyway (`Store.draftGaps()`, `Views.finishCheck()`). The "Workout saved" toast stays 5 seconds with an **Undo** button: it removes the session, puts the workout back as it was (`Store.undoFinish()`), and takes back this week's streak hit if that workout made it (`Streak.update()`).
- **Workout timer** — starts when a workout is started (Start workout, or opening a quick workout) and shows in bold green at the right of the top bar on the workout screen ("12:34", "1:02:34") and on the "In progress" card on the Workouts tab. It's worked out from the saved start time (`draft.startedAt`, `Store.draftElapsed()`), so it keeps counting while the app is closed; `updateTimers()` in `app.js` redraws it every second. The pause button saves `draft.pausedAt`; resuming adds the pause to `draft.pausedMs`, and paused time never counts. Typing a set's reps saves when (`loggedAt`). Finish on a workout over 3 hours asks "This workout ran 4h 12m. End it at your last logged set instead?" — "Use last set time" saves it as finished then (so it counts for that day and week; an already-ended week is re-judged), "Keep" keeps the full time. The time is saved as `session.durationMs` and shown in Past workouts ("· 52 min"); older workouts have none.
- **Quick workout** — + → Quick workout (`#/quick`) starts a one-off workout that isn't added to your cycle. It uses the normal workout screen (`Views.workout()` with `Store.draftWorkout()`, a stand-in workout built from the draft): an editable title (default "Quick workout"), "+ Add exercise" (the exercise search, which can also create a custom exercise and add it), each exercise starting with 1 set, "+ Add set", "− Remove set" (takes off the last set, once there's more than one) and Remove exercise, and no target reps. It's saved like any workout (`session.quick`, no `workoutId`, empty `plan`), so it counts for the log, maxes, the muscle map and Past workouts (with a blue date and a "Quick" tag). It doesn't move Next Up and doesn't count toward the streak.
- **Past workouts** — the link at the top right of Workouts (`#/history`, `Views.history()`) starts with a calendar of the days you worked out (history only, nothing planned on it; tap a day to list its workouts), then lists every finished workout, newest first (Today, Yesterday, then dates), grouped under week headers ("This week", "Last week", then "Oct 19 – 25") with each week's workouts and sets totals. Tapping one opens it (`Views.pastWorkout()`), looking like the workout start page: every planned exercise with its logged sets, a Log button and a pencil. The pencil opens that exercise's boxes, including empty sets so a forgotten one can be added. Save changes and Discard changes show once something's being edited; Delete workout is always there, and Back with unsaved edits asks first. Edits live in `pastEdit` in `app.js` until saved (`Store.updateSession()` / `deleteSession()`), then `Streak.rejudge()` re-judges that week and every week after. Logs, the muscle map and "last time" are always worked out from sessions, so they follow by themselves.
- **Extra sets** — every workout screen has "+ Add set", which copies the weight of the set above (if that's empty, the new set is too). On a planned workout it adds a bonus set for today (`extra: true` on the draft row, not on the plan); "− Remove set" only shows for those, so a planned set can't be removed (just leave it empty). They're saved and show in the log, maxes and actual sets. Swapping an exercise starts its sets over, without the extras.
- **Bodyweight exercises** — the weight box reads "BW + [ ]" and only holds added weight, so it can stay blank (`Library.isRepsOnly()`). Sets with and without added weight count as two separate exercises: sets with none use **max reps** (on the map, 8 → 10 reps = +25%), and sets with added weight use an estimated max of that weight, like any other exercise. Their Log has a switch between the two, and the finish summary and map list them separately ("Pull-Up (weighted)").
- **Workout progress badge** — a collapsed exercise shows ✓ once every set is filled in (reps, and a weight unless bodyweight), "1/3" part way, and nothing before the first set (`Store.draftProgress()`).
- **Cardio** — much less strict than lifting: it only adds to your record. Nothing turns red or says Missed, and it never touches the weekly streak, the cycle or planned sets. The rules and wording are in `cardio.js`; the data is `cardioPlans` and `cardioLog`. It has its own **Cardio tab** (`#/cardio`, `Views.cardio()`) for planning and looking back: "This week: X sessions · Y min", + Add cardio, planned cardio, a Run times graph, a calendar and every entry, newest first, with Edit and Delete. The graph (`Views.cardioGraph()`) has a switch between 1 mile and 5K (add a label to `RUN_GRAPHS` in `cardio.js` for another distance). It counts runs within 2% of the distance, treadmill or outside (`Cardio.runsOf()`), and works it all out from the log, so nothing extra is saved. Tapping a dot scrolls to that day on the calendar, with its entries showing (`'cardio-dot'` in `app.js`). Doing it happens where you lift. *Planned cardio* has a type, an optional name and optional numbers, on picked weekdays or **After every lift** (`afterLift`). `cardioRows()` in `views.js` shows checkbox rows: weekday plans under **Today's cardio** on the Workouts tab (`Cardio.rowsFor()`, with anything else logged today), and After every lift ones above Finish on every workout, quick ones too (`Cardio.afterLiftRows()`). Tapping one saves an entry with the planned numbers; if they aren't enough for an entry (minutes, or distance and time on a run), a short pop-up asks for just the time and distance that weren't planned (`Cardio.missingFields()`, `form.quick`), with no name or date. Tapping a checked row opens its numbers with Uncheck, which deletes the entry. One-offs and entries whose plan was deleted or moved show as checked rows too, with Delete instead. Each entry keeps its own copy of its numbers, so changing or deleting a plan never changes what's logged. *+ Add cardio* is in the + button's menu (as Quick cardio) and on the Cardio tab, with a date picker (today or any past date; a new entry is dated by the 3 am day). The form is one pop-up for everything (`Views.cardioForm()`, `cardioForm` in `app.js`). Runs show their pace and take minutes and seconds; other types take minutes. A run's distance has tappable buttons (1 mile, 5K, 10K, Half, Marathon; `RUN_DISTANCES` in `cardio.js`), since race distances aren't round numbers in miles: plan one with no time, and checking it off only asks for the time. A button also names a run with no name of its own.
- **More history** — every finished workout is in `Store.data.sessions` (oldest first), with date, workout name and each exercise's sets.
- New screens follow the same pattern: a function in `views.js` that returns `{ title, back, html }`, and a route in `app.js`.

## Getting it on your iPhone (later)

The phone needs to load the files from a web address. The easiest free option is GitHub Pages: put this folder in a GitHub repository, turn on Pages, then open the link in **Safari** → Share → **Add to Home Screen**.
